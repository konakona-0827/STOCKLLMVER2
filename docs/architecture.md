# 支撐研究架構與正式交易整合

## 2026-10-27 正式交易整合

新增 `trading.py` 使用實際 Agents SDK `Agent.as_tool`，讓正式主 Agent 呼叫研究及獨立反證子 Agent；`market_sessions.py` 用 TWSE FMTQIK 實際交易日驗證長期個股日線。子代理只有固定輸入及結構化輸出，沒有其他工具、交接或下單權限。

`agent_decision.py` 承接既有帳戶與券商工具；`trading_agent.py` 在原有決策驗證與交易前審查之間套用研究否決。正式執行器、資金複查、AI／人工持股歸屬及成交對照沿用交易底座。每輪 `support_research.json` 保留固定快照、雜湊、角色、錯誤與各子 Agent token 用量。

預設 advisory：兩方有效意見為 BUY 必要條件，任一 REJECT 否決；WATCH 可輔助既有策略，不能聲稱已通過以下嚴格研究合約。confirmed_support 另要求無資料限制、固定型態成立及兩方 RESEARCH。目前公司行動／事件／交易狀態尚未核實，不會假設這些條件已通過。SELL 仍沿用原有退出風控。

正式資料目錄由 `runtime_paths.py` 統一解析，程式分支與帳戶資料分開。研究政策讀取程式分支設定；`.env`、帳本與交易設定讀正式資料目錄。以下是保留的第一階段嚴格研究設計，適用離線 scan 及其 RESEARCH 資格。

## 研究問題

每天找出台股中「急跌後已反彈，回測原支撐帶未破，之後站回，目前價格仍靠近支撐」的可研究標的；同時保留將近成立但仍須等待的型態。市場是否恐慌與個股是否形成支撐是兩份證據。

`RULE_CONFIRMED` 表示本文指定的價格順序已出現，不表示支撐未來可靠、可以成交或適合個人的部位。排序分數只描述研究優先度，沒有校準成勝率。

## 模組

| 模組 | 責任 | 產物 |
|---|---|---|
| `contracts.py` | 完整日線、台股市場、價格調整、股數、時間及日曆驗證 | 不可變 Bar / Series |
| `support.py` | 因果特徵與固定 anchor 狀態機 | 型態、失效線、證據及技術分數 |
| `pipeline.py` | 背景與事件資料、逐股隔離、排序及快照 | 研究佇列、報告、任務包 |
| `agents.py` | 研究／反證的輸入輸出契約及固定裁決 | 雙方有效意見及最終研究狀態 |
| `demo.py` | 完全合成的正反案例 | 可重現的離線範例 |

支撐區在 episode 內固定；pivot 的形態日與真正可得日分開。使用當前已完成的 K，不能猜同日高低點發生順序。失效不會藉由降低支撐線消失。事件過期與重設均有交易日等待條件。

## Agent 工作方式

離線 scan 輸出兩份角色任務，並接受外部審查。正式交易整合入口會自動啟動 LLM 子代理；離線核心的資料與風控不依賴特定 SDK。

1. 數值層建立 `core`，包含截止時間、規則全文、可見日線、數值特徵、市場／公司資料與 evidence ids。
2. `packet_id = SHA256(canonical JSON core)`。core 同時包含 Agent 政策版本與實際任務文字；資料、背景、規則、任務或截止時間變動後，舊審查不可沿用。
3. 研究 Agent 解釋值得研究的原因、失效條件與缺口。它只能引用輸入證據，不能改價位或補造缺失歷史。
4. 反證 Agent 獨立讀取相同快照，檢查失效、追高、資料錯配及事件。第一輪不讀研究 Agent 的說服性敘述，以降低錨定偏誤。
5. 回傳 `RESEARCH / WATCH / REJECT`、證據引用、理由、風險、缺口與執行身分。`RESEARCH` 必須引用確認相關證據且不能仍有未補齊資料。
6. Python 驗證雙方身分、雜湊、欄位、證據與缺口。任一方否決即可 `REJECT`；有一方等待或驗證失敗則 `WATCH`。雙方皆通過且固定閘門無阻擋，才可列入 `reviewed_shortlist`。

相同模型的兩次執行仍可能共用偏誤；不同 agent_id 只是流程身分檢查，不是模型獨立性的統計或安全證明。第一版不驗證人為輸入資料的真實性，也不聲稱文字理由已被機器證實。

## 固定裁決邊界

- **資料拒絕**：混用盤中快照、無效 OHLC、重複／漏交易日、未完成日線、過時尾端、非單調可用時間、未核對公司行動、零量／停牌未分段。
- **研究拒絕**：固定支撐收盤跌破、公司邏輯明確失效，或任一方有效否決。
- **維持觀察**：尚未完整回測站回、已遠離支撐、收回支撐帶內、最新鎖漲跌停、20 日平均成交金額不足、公司／市場／事件資訊未知或過時、近期重大事件、無可驗證 PIT 宣告、雙方尚未有效完成審查。

資料通過只代表符合格式與輸入宣告。`actions_reviewed`、`point_in_time`、日曆來源及市場／公司狀態需要由可信資料提供者或人工程序核實；不能把布林值當成已完成外部查證。

## 市場壓力與部位

目前保存 `NORMAL / ELEVATED` 市場狀態與原始來源；缺少則觀察。下一階段才計算市場壓力事件。沒有將 39 次樣本的 72% 或 51% 寫進任何個股打分。

每支股票顯示一個**假設該股下跌 6%**的壓力價位，以及是否跨過固定失效線。這不是費半波動傳導模型、發生機率或最大可能損失。第一版沒有部位或相關性資料，因此不聲稱已評估整體帳戶承受度。

## 稽核與權限

離線核心結果可重現；報告保留資料雜湊、實際參數、形態日、可用時間、兩方原始意見與驗證錯誤。離線行情留在 git 忽略的 `local_data/`，產出在 `output/`。正式入口另載入共用 `.env`、帳本與券商執行器，所有正式產出留在忽略的 `data/`。子 Agent 無法直接存取這些憑證、帳本或執行器。
