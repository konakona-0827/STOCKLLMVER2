# 三 Agent 尋標架構 v1

日期：2026-10-28 建立，2026-10-29 完成首輪整合驗證（Asia/Tokyo）。分支 `codex/support-desk-discovery`；任務協定 `support-discovery-v1`。先建立尋標、研究、反證三個 Agent 的可執行架構，接著才逐步評估尋標品質。

## 角色與可擴充方式

| 元件 | 現在的責任 | 權限與輸出 |
|---|---|---|
| Python Head | 載入任務、分派獨立上下文、維持額度與交接 | 分配工作及驗證，不下單 |
| support_finder | 自行選探索方向、查市場、讀個股日線、提線索 | 三個唯讀工具；不可進場建議或部位計算 |
| researcher | 研究已提名股票的支撐與確認證據 | 獨立快照，研究結論與缺口 |
| reviewer | 尋找同一標的的反例與失效條件 | 獨立上下文，可否決 |
| Python Gate | 驗證代號、證據、日期、固定支撐與資料缺口 | RESEARCH／WATCH／REJECT |

尋標 Agent 是實際模型工具迴圈，不是替預排 top-N 寫理由。原有 researcher/reviewer 的角色與契約不變；尋標不是將其中一個角色改名。

`config/discovery.json` 的 scouts 是任務陣列，每個元素包含唯一 role、version、instruction。目前只有 support_finder，與後段兩位合計三個 Agent。未來可在設定加入「量能收斂」「產業輪動」等探索任務；runtime 以任務陣列建立獨立上下文、個別額度與稽核。每輪目前允許 1–8 個尋標任務，這是可調的保護限制，不是固定團隊編制。不同尋標者的提名採輪流交接並依股票／證據去重，保留每方理由。

同一個模型也可以建立不同上下文，但仍可能有相關錯誤；不同角色不等於不同模型。這階段不重新設計支撐規則或宣稱模型績效。

## 動態尋標工具

`market.py` 每輪取得官方現行公司名錄與單日全市場行情，取交集得到當輪可查範圍。這是代號驗證與資料目錄，不是固定的研究股票池。缺少或不合法的行情會列在 coverage，不以零值或前值補齊。

| 工具 | 由誰決定 | 回傳內容 |
|---|---|---|
| market_overview | Agent 選擇是否查看 | 產業分布、可查檔數、資料日期與額度 |
| search_market | Agent 指定產業、名稱／代號、排序、成交金額門檻及分頁 | 符合查詢的市場資料、匹配總數與下一頁狀態 |
| inspect_support | Agent 自行選擇股票 | 實際多月日線、固定支撐計算、證據 ID、最多最近 100 根原始日線及總根數 |

Python 執行查詢、取資料和數值計算；查詢方向、查看下一頁、深入哪檔與最後提名由模型決定。`config/universe_tw.json` 不再作 discover 或 observe 的隱性來源。沒有線索、API 失敗或額度耗盡時，皆不回退舊 19 檔。

目前僅台灣上市普通股。Advantest 只代表「已反彈、另日回測守住、再確認且仍靠近支撐」的形態意圖，不接日本行情；沒有資料支援時不宣稱已核實該日本個股。

## 證據與交接

1. 每個尋標任務取得自己的工具稽核、成功看過的股票與成功日線證據；不能看到其他角色答案。
2. 模型只回 symbol、history_evidence_id、rationale、missing_data，另附實際探索摘要與未探索範圍。
3. Runtime 核對該代號確實出現在自己的市場查詢結果，也成功讀過同一股日線；不存在的代號、未讀行情或假證據不能交接。
4. Head 配 lead ID，綁定市場 catalog_id、股票、日線 digest 及規則版本；多個角色對同股的線索去重但保留提名理由。
5. 後段只接收 Agent 正式提名的股票，不把所有讀過日線的股票悄悄當成候選。
6. 研究員與反證員讀取相同的已保存資料，不因交接再次下載新版行情。市場、日線、任務變動會改變證據或 packet ID。

尋標線索的狀態是 AWAITING_RESEARCH_AND_REVIEW。它不是已確認支撐或買進資格；是否成立由數值關卡與獨立雙方複核判定。原始價的公司行動、事件與交易狀態未核實時，仍固定阻擋 RESEARCH。

## 同輪資料與截止

市場名錄／行情在開始時凍結。個股資料依探索需求取得後立即深拷貝保存，跨尋標角色共用資料快取，不共用對話。相同股票整輪最多下載一次。市場與個股必須指向相同最新日線日期；跨日、錯代號、未來時間或不完整個股資料不能冒充可用證據。

交接快照使用實際取得資料中最晚的 as_of，保留每根 bar 原本的 available_at；不把後抓資料回填到較早截止。多個個股的交易日日曆不一致時停止合併。公司行動與事件缺口、來源新鮮度與 market DEGRADED 都會保留。

動態名錄可涵蓋千餘檔，不代表逐檔都已分析。市場名錄數、實際分頁看到數、讀過日線數、提名數、雙方複核數及待處理數分開顯示。空結果只代表本輪有界探索沒有線索。

## 預算與失敗

預設一個尋標任務：最多 8 次模型請求、12 次工具呼叫、4 個日線標的、3 條提名、每次最多 2,400 輸出 token、輸入 payload 最多 350,000 bytes。後段另預留最多 5 檔／10 次整對請求；實際只有 3 條提名時最多用 6 次後段呼叫，不強迫花完額度。

每次模型請求保存完整 usage（含可得的快取及 reasoning 細項）。缺 usage 保留 unknown 次數，不冒充零費用。API timeout、turn／tool／history／input 上限各自獨立，沒有自動重試。role_seconds 是每步前後檢查的合作式截止，不是可強制中斷整個程序的硬期限，也不是每日美元上限。

模型拒答、無效輸出、假引用、超限或 provider 失敗會記錄角色錯誤，該角色不交付線索，其他角色可保留結果。工具失敗也消耗額度並回傳受控錯誤；本輪標 DEGRADED，不把沒有成功日線寫成沒有機會。空結果也至少須成功查詢過市場才算完成。模型不能因任務指令修改額度或規則。

當日虧損 5% 停工需要可信帳戶損益。本階段不接帳戶、下單、簽署、EXIT／RUG 或通知排程，明確回報 account_loss_stop_enabled=false；不讓模型猜測帳戶虧損或宣稱已有這項保護。

## 保存與重播

每輪保存 discovery_plan.json、market.json、discovery_histories.json、discovery.json（模型回應、工具選擇、回應 digest、用量與提名）。有交接則另保存 input.json、rules.json、report.json、評語及原有帳本資料。manifest 保存額外尋標產物的 digest。

官方原始 HTTP JSON 另保存至快取目錄 raw/<SHA256>.json，來源附 raw_archive_file。更新同一 URL 的快取不會覆蓋舊內容；需要跨電腦保留原始證據時應連同 local_data 備份。市場下載或設定階段失敗也有 latest_attempt／failures 紀錄，OpenReport 會顯示最後嘗試狀態與實際報告日期。

真實觀察沿用 transaction 中發布、成功後提交帳本與 committed marker 的流程。無提名或離線示範不寫觀察帳本，使用 completed marker 及獨立 latest_discovery 指標，不把它冒充有帳本的觀察報告。工具／模型回應與報告文字都視為資料，HTML 輸出轉義。

`python -m support_scout discovery-replay RUN_DIRECTORY` 檢查產物 digest，重新執行保存的模型工具選擇，逐回合核對輸入 digest，重建相同提名及研究裁決。重播不連網、不重新問模型。原始網路失敗而缺模型回應的角色不能完整重播，會明示失敗，不偽造成功。

## 本階段驗收與後續

最低驗收為：舊 19 檔外的代號可由模型工具選擇並交接；改工具回傳會改提名；未查市場／日線不能提名；偽造證據、未來資料與超限被擋；任務可擴充且隔離；重複股票去重；完整輸入可離線重播；三方同意仍不能越過原始價限制。

2026-10-29 整合驗證：154 項離線測試全部通過。獨立審查另重跑尋標及工具測試，確認修正重播輸入／報告可能被改而仍顯示 MATCH、零探索卻宣稱完成，以及資料工具失敗未標降級的問題。

小額真實驗證保留於本機 `output/discovery-live-smoke/20261029T095950-13e1257f9f/`。使用 gpt-5.6-luna，尋標依序呼叫市場概況、兩次自行設定的市場查詢及個股日線工具：市場可查 1,088 檔、實際看過 24 檔、讀日線 1 檔、提名舊池外的 3037。後段研究員與反證員各完成一次真實請求，結論均為 WATCH。這是交接案例，不是股票推薦或形態品質的驗收結果。

該輪尋標 5 次請求加後段 2 次，共 7 次，保存的用量合計輸入 81,895、輸出 2,995 token。市場最新日與預期均為 2026-10-28，但部分公司行情缺漏／不可解析，整輪保留 DEGRADED。資料日期沒有冒充當日盤中；沒有連接券商或下單。該輪已以保存的工具回應及研究快照完全離線重播為 MATCH。

下一階段才逐步擴充探索廣度、更多市場歷史工具與公司事件來源，建立使用者認可的正反例、固定參數後的前向驗證及成本統計。現在不以 20–40 條為硬目標，不以空名單推論全市場無機會，也不宣稱已有選股績效。
