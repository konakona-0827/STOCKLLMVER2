# 日常使用與中文欄位

## 啟動與確認

在 japan-support-desk 資料夾雙擊 `Dashboard.cmd`。保留終端視窗，它就是程式；也可在該資料夾執行 `python -X utf8 -m support_scout serve --port 8765 --open-browser`。同一份專案重複開啟會沿用原服務。

依使用者指定，啟動器會明確在外部Google Chrome應用程式開啟Dashboard，不使用Codex右側或系統預設瀏覽器。請在新電腦安裝Chrome；找不到時會顯示手動網址，不自動回退到其他瀏覽器。

開啟啟動器顯示的網址（通常 <http://127.0.0.1:8765/#scan-control>；舊版占用時會改用8766等後續埠），在「掃描與稽核」依序確認：

1. **程式連線正常**：本機服務剛剛有回應，旁邊顯示日本時間，每5秒更新；不呼叫行情或付費模型。
2. **掃描器運行中**：背景執行緒存在。再看**自動掃描已啟用**；若停止，按「啟動自動掃描」。
3. **分析中／交易時段／午休或休市**：待命不代表程式關閉。日本09:00、10:00、11:00、12:30、13:30、14:30、15:15各一輪，每個交易日最多7輪；休市不分析，錯過不連續補跑。
4. **上次結果與最新完成報告時間**：DEGRADED表示該輪仍有資料或研究缺口。看到「有新報告」請按「重新載入最新報告」。頁面本身不會自動換成新一輪決策。

若顯示「程式連線中斷」或網址連不上，重新執行 `Dashboard.cmd`。能看到以前的HTML報告不能證明服務還活著。關瀏覽器不會停止掃描；關終端、關機或睡眠會停止／暫停。停止掃描按鈕只停未來自動作業，已開始的一輪會完成；停止設定會保存。

更新程式碼後，雙擊 `Dashboard.cmd`。遇到可識別的本專案舊版，啟動器會先暫停舊版排程，再開啟可用埠上的新版，不強制關閉程序；新版已存在時直接開啟它。舊版有分析執行中則先等完成再開。使用啟動器開啟的新網址，舊分頁不會自行變成新版。

「立即手動分析」明確重跑當前時段，會使用模型API，也可能寄出符合條件的操作通知；仍不越過交易時段和風控。查看頁面、重新載入、看中文欄位都不會要求模型重新分析。

## 看哪裡與如何運用

「總覽比較」保留決策總表、觀察名單與可展開的尋標交接比較；表格可獨立捲動並固定表頭。先看結論、買入類型、條件、金額、情境虧損。點股票代號會進入「個股研究」，下拉選單一次顯示一檔，再切換「決策與價位、走勢與型態、研究／反證、JSON中文說明」。成交回報與郵件狀態放在「持倉與通知」；掃描控制與技術稽核另放「掃描與稽核」。分頁切換不增加API呼叫。

0.15.0三處股票顯示順序一致，附上#順位與原因：已確認持倉的有效減碼／退出、有效買入提案、本輪尋標重點、其他型態潛力、波動觀察、一般觀察、暫不進場、資料未通過。只有正數建議金額及完整價位、或確認持倉操作，才進入操作提案類；觀察股不因有參考價而升級。重點觀察依本輪尋標員提交順序，其餘依型態成熟度與研究分數，最後用代號穩定排序。這是先看順序，非勝率；純顯示排序不改Python原部位分配或已保存快照。

所有分頁上方都有「程式目前狀態」，例如「目前休市或午休，程式待命；下次掃描11/04 09:00」，並說明本輪是否有有效提案。「本輪處理情形」可展開看掃描檔數、尋標提交數與研究回覆缺口。有新報告時出現載入按鈕；新版介面發布則自動切換。若正在輸入成交回報，會保留原頁並提示先保留輸入內容。瀏覽器可能不允許網頁關閉人工開啟的分頁，因此採同分頁換成新版；舊版尚無此功能時仍需開啟啟動器提供的新網址。

2026-11-02驗證：392項回歸通過，操作提案有效性、0金額／未確認持倉不升級、尋標順位、失敗狀態說明與更新互斥另有測試。以15:15保存的20檔真實報告呈現，決策表／觀察表／選單前四順位一致為4063、6027、7974、6758；未改來源或決策。新版程式實際透過retire安全交接並沿用8769埠，啟用設定保留；已開啟的新版分頁自行載入新介面，未要求模型重跑。少數更舊分頁無法透過瀏覽器控制關閉時保留，但舊掃描器已暫停。

| 欄位／狀態 | 意義與用法 |
|---|---|
| `opportunity_decision` | 目前積極人工機會通道的結論，日常先看這個 |
| `PROBE_BUY_REVIEW` | 條件式人工試單評估，仍要看觸發、價格上限、金額及人工核對 |
| `WAIT`／`WATCH`／`AVOID` | 等待／觀察／暫不進場，不寄信；即使附有參考價也不代表可買 |
| `research_status` | 分開標記未研究與完成研究；20檔是研究範圍，每輪最多4檔進一步雙方研究 |
| `execution_plan` | Python按你的預算與風險計算部位；建議金額0表示本輪不建議新增買進 |
| `entry_reference` | 試算用進場基準，不是保證成交價 |
| `entry_trigger_reference` | 條件式進場需先達到的參考價，達價後仍須核對其餘條件 |
| `entry_ceiling_reference` | 評估價格上限，超過須重新評估；不是整段區間無條件可買 |
| `invalidation_reference` | 所屬通道的失效或戰術風險線；不等於已掛停損單 |
| `target_reference` | 策略目標；短線按實際進場價重算股價+2%，不是上漲預測或淨利保證 |
| `estimated_loss_jpy` | 部位、成本與跳空假設下的情境損失，不是最大損失保證 |
| `market_quote.quoted_at` | Yahoo來源報價時間；必須比對現在時間，並以券商報價重驗 |
| `market_quote.age_seconds`／`usable` | 都以當輪快照檢查，開著頁面之後仍會過期；不是持續更新的即時可用旗標 |
| `latest_close` | 最新完整日線收盤；盤中通常仍為前一交易日 |
| `priority_score` | 安排研究先後的分數，非上漲機率 |
| `selection_reward_risk`／`net_reward_risk` | 選股／成本情境後的報酬風險倍數，非勝率 |
| `trade_decision` | 原較嚴格正式資格通道；與積極人工評估分開，不混用兩套風險價 |

中文欄位頁將比例0.02顯示為2%，空值顯示「未提供／不適用」，與數值0分開。無法核實的事項不會因加上中文標籤變成已核實。

你核對後自行在券商操作。真正成交後，填入「手動成交回報與持倉」的買賣、股數、實際價、費用、時間，勾選「我確認已實際成交」再儲存，下輪才會參考持倉與成本。沒有回報不推定成交。郵件只提醒有效操作事件，WATCH不寄；不需守著頁面，但程式和電腦需保持運作。
