# Python決策總表與金額試算

0.9.0將三Agent結論交Python整理成 `execution_plan` 與 `decision_brief`，頁面、Markdown、JSON及郵件共用欄位，沒有第四個模型或訂單能力。

個人設定在忽略的 `local_data/sizing_settings.json`，格式參考 `config/sizing.example.json`。新checkout沒有本金或風險額度就不建議正數部位，不把範例資金當真實帳戶。

## 公式與限制

- 單筆情境虧損上限＝設定本金×單筆風險比例，是上限而非必須用滿。
- 初次單檔試單資金上限預設25%，可調；另以新建部位的合計風險預算限制多檔，不重複使用整份本金。
- 建議金額取剩餘估計現金、單檔資金上限、單筆風險上限除以風險率、剩餘新風險預算除以風險率的最小值，再向下取整。
- 情境風險率取Agent參考計畫與價差／跳空重算的較大者。H-002沿用成本後風報門檻；H-003／004／005依使用者最新偏好，以不計券商成本的策略風報判定選股資格。實際成本情境仍計入風險與金額限制，並分別顯示價格目標及成本後估算。
- 只對PROBE_BUY_REVIEW給正數；WAIT／AVOID、缺預算或無有效價位為0。已有確認持倉不自動新增買入。

資金以使用者本金與確認成交現金流推算，買入扣價格與費用、賣出加成交款減費用，因此實現虧損也會減少估計現金。不是券商餘額，不知道外部提款、入金或漏報成交。沒有可信帳戶淨值或即時損益，不能宣稱完成日損停工。跳空仍可能超過情境虧損上限。

## PayPay金額指定與整張

2026-10-30核對[PayPay官方日本株規則](https://www.paypay-sec.co.jp/stock/rule/)：立會時間內買方基準價格加0.5%、賣方減0.5%，費用相當額含於報價。機會政策v2與金額試算使用每邊0.5%及額外0.5%跳空緩衝，仍不是保證成交價。

[官方商品頁](https://www.paypay-sec.co.jp/stock/)顯示金額指定可用1日圓單位，起買額依資金來源可為100、1,000或10,000日圓。本機試算採至少1,000、以1,000向下取整，這是程式的保守取整設定，不宣稱券商增額必須1,000。若資金來源起買額為10,000，須調高設定。可切 `BOARD_LOT` 依100股整張試算，買不起不以零股冒充整張。

AMOUNT_JPY的換算股數＝建議金額／含買方價差的參考價格，只是估計；該標的是否在PayPay名單、最新報價、實際小數股數及可接受精度仍需核對。沒有查證研究池每檔的券商資格，不能把正數試算當可直接送出的訂單。

手動成交可輸入最多8位小數的正數股數，持倉運算以Decimal處理，避免0.1＋0.2後賣0.3被浮點誤判超賣。未確認成交仍不計入。記錄實際成交數量，不使用試算換算股數假造持倉。

## 欄位與重播

每列保存代號、名稱、結論、買進／等待條件、參考進場／失效／主要阻力、建議金額、換算股數、情境虧損、試算狀態及人工核對項目。本輪另存本金、可用現金估計、新投入／新風險合計與設定digest，均在本機忽略的報告資料夾。

在觀察開始時凍結sizing_policy，帳本提交與機會重算完成後再算金額。execution_plan為派生欄位，不誤加入來源快照hash；原始行情或綁定遭破壞仍由上游資料與決策閘門拒絕。

歷史案例可另外套用目前資金參數做SIMULATION_ONLY試算，保留原模型評語與歷史價位，不改原案例、不寄信，也不稱當時已知資金設定或今天買點。

通知主體採繁中決策摘要，不只寄原始JSON。新的未寄狀態會把同檔舊PENDING標成SUPERSEDED，避免先寄過期建議；已寄或結果不明仍留原稽核。單純as_of變更不重寄同狀態。
