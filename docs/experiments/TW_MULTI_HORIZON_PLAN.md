## 決策與研究問題

保留短期大量尋找機會的方向，同時研究中短波段及長期企業成長。讓 A、B、C 在相同市場期間，以獨立策略與帳戶紀錄驗證，主要比較扣除成本後的資金效率與風險。原對話的 40%／40%／20% 是研究工時分配，並非投資資金比例。

| 研究線 | 要回答的問題 | 主要期限 | 首輪研究設計 |
| --- | --- | --- | --- |
| A Quantity | 大量小額短期機會，扣除成本後是否仍有正期望值？ | 3～5 日，另觀察 10 日 | +1.5%／-1%、+2%／-2% 兩組路徑情境 |
| B Balanced | 趨勢、產業與事件篩選能否改善資金效率？ | 5～20 日，另觀察 60 日 | +3%／-2%、+5%／-3% 作初始價格基準 |
| C Quality | 財報及產業研究能否較早發現成長機會？ | 3～12 個月 | 63／126／252 交易日價格基準，後接公告時點財報與事件 |

上述停損、B 的固定障礙與交易日換算是本次為可執行研究設定的起始假設，並非對話已證實的最佳參數。B 的最終策略應研究動態目標與退出；固定障礙只作比較基準。C 的價格標籤不代表成長股模型已完成。

預測期限、持有上限、重新分析頻率分開設定。`protocol.json` 的 `forecast_horizons_trading_days` 控制本版標籤視窗；`planned_max_holding_trading_days` 和掃描／檢視頻率目前只是下一階段策略設計，不會讓標籤引擎提前截斷視窗。

## 本次落地範圍

完成實驗立項與第一階段的離線標籤工具，作為改造入口：

- 封存對話來源，固定 A／B／C 定義與開發順序。
- 使用 Python 標準函式庫建立獨立 `research.multi_horizon` 入口，不匯入正式設定、憑證、券商、LLM 或帳本模組。
- 產生多期限的 TP／SL／到期標籤、扣除成本的情境損益與占用交易日數。
- 對交易日缺漏、無成交量、資料未成熟及日線雙觸價明確處理。
- 每個 run 保存資料快照、協議、輸入與實作 SHA256、分線統計；原有 Dashboard／正式策略選擇不變。

目前仍未完成完整歷史資料集、量化選股模型、機率校準、組合回測、三個前向模擬帳戶或自動排程。本次合成資料執行只驗證工具，不構成收益證據。

## 共用四層架構

1. **短期價格機會**：量化掃描與 3／5／10 日路徑模型；輸出校準後的先停利／先停損機率、淨期望值、預期持有日數及不確定性。
2. **中期市場狀態**：20／60 日趨勢、波動及產業相關性。保留套用與未套用過濾器的候選，便於消融比較。
3. **企業與產業研究**：以公告可取得時間串接營收、財報、新聞與產業事件。LLM 提供有來源的研究及事件分類，不以主觀信心充當機率。
4. **執行與風控**：以程式處理最新報價、停利停損、持倉與資金限制，沿用經驗證的正式執行契約；最終才接實盤入口。

行情掃描初始設定每 5～15 分鐘；LLM 依重大事件觸發、持倉每日 1～3 次、財報／產業每週或事件觸發。實際頻率須在群益行情權限與速率限制核實後設定。增加股票數量不應等比例增加 LLM 呼叫次數。

## 現況與可沿用部分

`develop` 已整合 Agent／LLM 決策、Python 驗證、正式風控、執行帳本與對帳。`strategy_experiment.py` 有獨立策略資金、版本與每輪紀錄，可作前向模擬的遷移來源。

目前 `ExperimentStore.record()` 的賣出損益僅扣手續費，尚未扣賣出證交稅；賣出所得即時回到模擬現金，也未完整表示 T+2 交割。既有 `paper_portfolio.py` 同樣不是本計畫所需的完整成本與交割引擎。不能將舊結果與新實驗直接視為同一成本口徑。

原應用日線管線主要提供最多 22 個已結束交易日，不足以訓練 60 日或 3～12 個月模型；須另建立長期研究資料集。新工具先接受使用者準備的 CSV，不將當前股票清單當作歷史完整股票母體。

## 資料與實驗紀律

- 市場日曆使用明確交易日，包含臨時休市的版本；停牌不可當作市場休市跳過。
- 股票母體需保留當時上市／上櫃、下市、停牌與交易限制，避免只挑今日存續股票。
- 同一股票供應區間內缺少交易日就停止研究；不能把缺資料的三週錯算成五個交易日。歷史開始／結束仍需從資料來源解釋，工具無法單憑 CSV 判斷上市與下市。
- 使用當時可取得的特徵與公告時間；價格的除權息、分割、現金股利及交易限制，須由資料準備層處理並在 `dataset-note` 記錄。原始日線、調整日線與實際現金流不可混用。
- 訊號取收盤後，最早下一交易日進場。盤中零股不在進場當日退出。日線本身不能證明零股委託可成交。
- 時序切分訓練／校準／驗證／封存測試；邊界清除跨越切分的未完成標籤，至少依最長標籤期限設定 purge／embargo。隨機打散日線會污染未來資訊。
- 實驗登錄保留 protocol、資料、模型、提示詞、程式版本與 run ID；變更規則建立新版本，不覆寫已完成 run。
- 保存保留／排除的候選與原因，分別比較量化、加趨勢、加新聞，以及加 LLM 的增益和費用。

## 成本、交易制度與版本

初版只涵蓋一般股票跨日情境：買賣兩邊手續費、可設定折扣與最低費用、賣出證交稅、兩邊滑價情境。預設費率 0.1425%、折扣 1、最低費用 20 元、每邊 10 bps 滑價均是研究假設，須以實際帳戶條件覆核；手續費與稅在本工具採向上取整元的保守情境，並不宣稱等同券商逐筆收費。

一般股票賣出證交稅 0.3%，依[財政部稅務入口網](https://www.etax.nat.gov.tw/etwmain/tax-info/understanding/tax-knowledge/rwG2M1N)。手續費可由券商按成交金額自行訂定，參考[證交所投資指南](https://www.twse.com.tw/zh/about/company/guide.html)。本版不套用當沖優惠稅率，也不涵蓋 ETF、債券 ETF 或其他稅別。

交易時段須依生效日期版本化。依[證交所 1150016624 號公告](https://twse-regulation.twse.com.tw/tw/int/DAT01.aspx?FLCODE=FE399225)，2026-12-07 起盤中零股 08:30 收單、09:00 首次撮合；本次離線日線研究不改動正式 Scheduler。接入前向模擬時須加入新舊版本邊界測試，並核對上櫃規則與券商支援情況。

T+2 在組合回測及前向模擬層建立交割現金日曆、買賣應收付與可再投入限制；本版逐筆標籤沒有資金再投入，因此不宣稱已模擬交割。不能把未交割賣出款直接當可任意循環使用的現金。

## 里程碑與驗收

| 階段 | 狀態 | 產物與驗收 |
| --- | --- | --- |
| M0：立項與研究入口 | 本分支完成 | 對話封存、A/B/C 協議、離線標籤、輸入／實作版本、合成範例與測試 |
| M1：歷史資料與模型 | 待實作 | 多年價格／母體／公司行動／公告時點資料；3/5/10/20/60 日校準與樣本外比較；C 的財報及長期基準 |
| M2：事件驅動組合回測 | 待實作 | 共用成本、委託未成交／部分成交、零股限制、交割現金、相關性、資產曲線及基準；A/B/C 獨立帳戶同時段比較 |
| M3：獨立前向模擬 | 待實作 | 每條線新帳戶與新開始日、不承接正式持倉；30～60 交易日先看執行可靠性，C 等待足夠長的成熟視窗 |
| M4：評估與配置 | 待實作 | 依封存樣本與前向證據決定模擬配置，再決定小額實盤驗證方案 |

M1 的校準輸出至少包括 `P(TP,h)`、`P(SL,h)`、到期分布、`E(Net P&L)` 與預期持有日數。以樣本數、校準曲線、Brier score 及期間穩定性檢驗，未達標時保持不可用，不輸出偽精確機率。不能將本工具的全樣本描述性觸價比例直接送給下單器。

M2 起比較：扣除交易及 API 成本的淨期望值、總資產報酬、最大回撤、資金占用／交割天數、每萬本金每日收益、周轉率、曝光及產業集中度，並對照同期間大盤與可投資買入持有基準。分別報告不同市場狀態、重疊樣本與信賴區間；不以勝率單獨選策略。

本輪接續工作以 M1 為先：先完成可追溯的多年資料與交易日曆，再鎖定時序切分與首個量化基準，最後才加入趨勢與 LLM 過濾器。M0 的 synthetic run 不能作為進入 M4 的依據。
