# 獨立模型與實作審查

審查日期：2026-10-27。審查角色：`model_review` 子代理；未參與核心程式撰寫，只修改本文件。

本次審查的是台股候選研究的第一階段骨架。它採用 **Agent 任務匯出／審查匯入**，尚未接入自動 LLM 執行器、真實行情 adapter、績效回測或下單流程。合成測試中通過雙方審查，不表示已讓真實模型選出任何股票。

## 審查結論

**可接受為第一階段離線研究原型。** 固定數值層、研究方、反證方與裁決層的分工合理，可作為下一階段台股資料串接的基礎。本輪發現的因果性、快照綁定、錯誤輸入及跨休市事件問題均已修正並覆核，目前沒有阻擋這個原型範圍的未解實作問題。這項結論只涉及研究流程及實作邊界，沒有證明支撐規則具備交易優勢。

## 已覆核的設計

- **支撐因果性**：pivot 必須等待右側兩根完整 K 可得後才識別，形態日期與可知時間分開。反彈、回測及站回發生於不同交易日，不推斷同日高低價的先後。
- **固定支撐**：同一 episode 內不下移 anchor；收盤跌破固定下緣即失效，保留失效紀錄並等待重設。失效／無型態不顯示可競爭的研究分數。
- **目前價格位置**：已確認型態仍須通過靠近支撐、最新未收回區間、最新未盤中跌破下緣、流動性及鎖漲跌停等閘門。歷史上確認過，不等於現在仍符合候選條件。
- **資料閘門**：拒絕盤中快照冒充日線、無效 OHLC、非有限數、日期重複或缺漏、未完成日線、過時尾端、非單調可用時間、未核對公司行動、零量或停牌未分段。
- **未來資料隔離**：截止後的日線不進特徵及任務快照；已執行完整檔與截止前綴檔輸出一致的測試。交易日曆快照只綁定截止前可見 sessions。
- **審查快照綁定**：`packet_id` 包含可見日線、背景、規則、日曆來源及可見 sessions，以及實際雙方任務文字與 policy version。資料或政策改變時，舊審查不能直接沿用。
- **有效否決**：反證方的有效 `REJECT` 能阻擋候選；缺任一方、同一身分、錯誤引用、缺證據、重複角色、待補資料或格式錯誤，都不能升為 `RESEARCH`。雙方同意不能覆寫固定資料及型態閘門。
- **休市期間事件**：以事件發生與公告的較晚時間對照最新完整 K 收盤；收盤後至研究截止的重大事件，即使經過多日休市仍維持 `WATCH`。查核窗口須覆蓋最新收盤至未來緩衝期，不能只提供未來事件表。
- **輸出界限**：只輸出 `RESEARCH / WATCH / REJECT`；技術佇列可保留仍待補公司資訊的標的，最終 `reviewed_shortlist` 另須通過全部閘門。分數明確標為未驗證的研究優先度，不是勝率。

## 審查中發現的問題與處理

| 問題 | 處理及覆核 |
|---|---|
| 舊 K 延遲補登，可能把衍生訊號的可知時間回填到過去 | 已加入 session 順序下的 availability 非遞減驗證；非單調版本須重建快照 |
| 確認後最新收回支撐帶內，仍可能留在候選 | 已加入 `LATEST_CLOSE_NOT_ABOVE_ZONE` |
| 失效型態仍留有正研究分數 | 已將失效／無型態分數設為空值 |
| 改變交易日曆來源仍可沿用審查 | 已把日曆 provenance 與可見 sessions 綁入 core；新增回歸測試 |
| root／calendar 非物件會產生未處理的 AttributeError | 已轉為全域 DataError；新增邊界測試 |
| 不合法 packet_id 型別會中止整批審查 | 已記錄 `MALFORMED`，不讓單筆壞引用造成整批中斷 |
| 長假／颱風休市使重大事件掉出「前一日至後三日」窗口，但最新 K 尚未反映事件 | 已加入最新 K 收盤至 cutoff 的事件閘門；以 `max(event_at, announced_at)` 判斷，邊界保守維持觀察。新增多日休市、晚公告及缺少查核起點的回歸測試 |

## 執行驗證

獨立執行 `python -m unittest discover -s tests -v`，原 36 項測試全部通過；修正後再執行 `python -m unittest discover -s tests -q`，最終 **42 項測試全部通過**。另以臨時記憶體資料檢查日曆來源變更、壞 calendar 型別、壞審查 packet_id，以及長假期間未反映事件的情境。已覆讀最終事件閘門及其測試，確認反例無法再升為 `RESEARCH`。

測試驗證的是輸入契約、數值規則、時間隔離、角色審查及 CLI 行為；測試資料與審查替身均為合成，不驗證真實行情品質、模型論證品質或投資績效。

## 尚未驗證的部分

1. **資料真實性**：`actions_reviewed`、`point_in_time`、停牌、鎖漲跌停、交易日曆與公司論點目前依賴輸入宣告。程式只驗證合約，未向交易所或公司公告逐一核實。
2. **Agent 的實際獨立性與內容品質**：不同 `agent_id` 是流程身分，不是獨立模型或防偽證明。引用存在的 evidence id 也不保證文字結論符合該證據；尚無語義驗證、自動調度、逾時、費用上限或模型服務測試。
3. **規則與排名效力**：60 根日線、8% 回撤、ATR 區間、反彈幅度、等待期限及權重都是可測試假設，尚未做門檻敏感度、樣本外驗證或跨市場比較。未確認量縮加分能改善候選結果。
4. **可交易性與成本**：日 OHLCV 無法證明失效價可成交；尚未模擬跳空、鎖跌停、滑價、稅費、成交量限制與部位關聯。假設個股下跌 6% 只是單一情境，不是費半傳導模型或損失機率。
5. **歷史研究有效性**：今天下載的歷史檔不能改寫 available_at 後冒充當時資料。仍需當時股票名單、下市／停牌樣本、正確公司行動版本、成熟的 5／20／60 日結果，以及對重疊候選的群聚處理。

貼文的 39 次費半事件尚未取得原始事件清單與完整算法重算；其收高比例、再崩機率及信賴區間均未成為個股模型參數。相關解讀見 [貼文分析](conversation-analysis.md)。

## 下一階段驗收重點

先接 120–260 日台股完整日線及公司行動／交易日曆來源，保存可重現快照，對照人工正反例。之後才接真實雙 Agent 執行，確認失敗可觀測、舊快照不可混用且否決有效。最後做時間分離的樣本外比較，檢驗等待回測站回是否相對「只看跌深或反彈」改善失效率、途中回撤及成本後結果。
