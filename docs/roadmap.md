# 分階段路線

## 一：研究架構與可執行分工（本次）

完成快照合約、固定支撐狀態機、Head 分派、研究員與反證員獨立請求、證據與失效裁決、稽核及有界 API 轉接器。離線示範與模擬 API 端到端測試完成；真實 API 與市場資料尚未驗證。

## 二：接可靠台股資料（下一步）

建立獨立唯讀 adapter，先取得 120–260 根完整日線、真實成交金額、實際日曆、公司行動／還原基準、停牌／鎖價資訊，以及公司公告與事件。股票池要版本化，上市與上櫃來源分開。

既有 STOCKLLM 最多 22 日且是原始價格的日線不能直接滿足 60 日合約。今天下載的歷史檔保存真實取得時間，不能改成歷史收盤時間來假裝當時已知。取得完整資料前不以調低門檻來湊股票。

先對照一批人工挑選的「反彈後回測」、「反彈未回測」、「確認後已遠離支撐」、「失效」台股正反例；驗收是價位可重算、所有缺口有原因。同一快照對兩方各跑一輪，觀察反證員是否確實找出錯誤。

## 三：逐日回播與模型檢驗

先凍結規則與參數，再分開設計期、驗證期與樣本外期間。比較未篩選、只看跌深、只看反彈、回測後確認等基準，包含未成立案例與當時股票池，避免只挑勝者。

觀察確認後 5／10／20 日：支撐跌破率、最大不利變動、延伸程度、候選覆蓋與後續報酬。尚未到期的樣本保持 pending，重疊候選需分群，不能當獨立樣本。若模擬交易，另加成本、跳空、鎖價與成交假設。

這些結果才回答模型是否值得繼續使用；獨立程式審查不等於證明投資優勢。

## 四：穩定後擴充

按需要增設「突破後回踩」與「上升趨勢高低點」等獨立型態，分別評估；再考慮收盤後定時研究、外部公告查證與人工報告。持倉、5% 帳戶停工、執行與核准流程是另外的工程範圍，須有可靠帳戶與交易證據才實作。
