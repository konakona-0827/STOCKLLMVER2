# 分階段執行

## 階段一：可驗證的研究骨架（本次）

完成台股日線合約、固定支撐狀態機、技術佇列、雙 Agent 任務與審查契約、離線情境及因果性測試。沒有真實選股績效，沒有自動模型執行器。以 RESEARCH / WATCH / REJECT 保存研究資格。

## 階段二：接完整台股資料

接使用者已能取得的台股行情，建立獨立唯讀 adapter；上市／上櫃來源明確區分，補公司行動、真實交易日曆及公司／事件查核。先保存一批 120–260 日的可重現快照，對照人工挑選的正例、假反彈、跌破、已追高標的。

驗收：同一快照可重現；所有不足有原因；不需要模型才能驗算價位；原系統交易流程不受影響。若第一批只有 22 日，先補資料，不能把門檻改低來勉強選出股票。

## 階段三：讓研究 Agent 實際跑一輪

實作 provider-neutral 調度器：研究方與反證方分開執行、有個別 timeout、費用／回合上限及失敗記錄。先對固定快照執行，驗證引用與否決有效；再按每日收盤後一輪處理新快照。新增的網路資訊要有 source、published_at、available_at，不能混入已封存的歷史包。

驗收：資料和規則決定數值，Agent 負責論證與反證；同意不是勝率；未完成、錯誤或過時審查維持 WATCH。

## 階段四：逐日回播與模型審查

在時間上切開規則設計、驗證與樣本外期間，使用當時股票名單（包含下市／停牌）與可得資料。比較未篩選、只看跌深、只看反彈、完整回測站回等基準。參數搜尋與最終測試分離，避免為了某張 Advantest 圖過度調參。

衡量：未來 5／20／60 日報酬、最大不利變動、支撐失效先於正向目標的比例、候選覆蓋率、鎖跌停／跳空、成本與成交假設。未成熟期限保留為 pending，不湊相同分母。重疊事件按危機／日期群聚評估區間，不能把連續候選都當獨立試驗。

確認是否有穩健優勢後，才討論更頻繁掃描與部位方案。這份路線不會自動建立排程或啟用交易。
