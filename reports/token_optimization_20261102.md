## 為什麼沒有交易

1. 當時可用資金約 NT$5,460；15%／25%／30% 新倉上限約 NT$819／1,365／1,638。3017、2454 等標的連 1 股都超過最高配置，2345 加費用後也超過。高量化排名不等於適合這個帳戶。
2. 2317 等較低價標的，到最近可驗證壓力的毛空間很小；雙邊最低費用各 NT$20、價差及交易稅足以吃掉報酬。把遠方前高當成已越過近端壓力的目標，不能解決這個問題。
3. 2603 趨勢相對強，當前 ask 卻已到最高可用價位附近；沒有更高、可驗證的合法目標，不適合追價。
4. 現有 1101、2891 部位的原計畫或風險，沒有充分支持立即賣出的新證據；單純為了交易頻率賣出會再付出成本。
5. 已啟用 PLANNED_LIMIT，但策略一部分條文仍要求從 ask 起算，和等待回落限價的執行契約矛盾。這會漏評回落情境。

本次沒有調低手續費、提高預算、放寬 2%／1.5／0.5% 門檻，亦未恢復每日試單。離線有限情境搜尋對今天保存的候選仍沒有找到通過的組合；這不等於證明所有可能計畫都不可行，更不應改用無根據的目標湊出交易。

## 已實作的調整

- Python 先讀取同一正式帳戶及交易歷史，放入初始輸入；不再花兩次模型往返索取既有資料。刷新帳戶仍會使舊行情觀察失效。
- 初始只傳最近 5 筆日線、3 筆盤中抽樣，標示完整筆數及截短狀態。保留所有合法價位、資料狀態、持倉、成本、可賣量與剩餘買進計畫；完整原始資料可由 `get_research_data` 取得。Python 驗證及本機稽核繼續使用未截短資料。
- 日線、盤中抽樣、價位採 columns/rows 無損表格。重複排名解釋、來源網址等改為按需讀取，並保留原始稽核。
- 新增 `entry_screen.py`：按現有費用、配置、風險及近端壓力預算數字情境，同時比較現價與有資料依據的回落限價。結果只供評估，不能自動下單、代替訊號確認或代表已證實獲利能力。列出的失效價仍須模型及獨立審查確認其結構依據。
- 研究由有待驗證的交易情境觸發，不再強制每輪至少研究一檔；所有 BUY 仍須原來的兩方研究。搜尋也依新買候選或持倉事件疑點觸發，不機械式每輪查一次。
- 加入多檔批次查價工具，降低多檔交易或持倉重新查價的模型往返；研究資料工具不會冒充即時行情觀察。
- 統一 PLANNED_LIMIT 與一般即時買進的入場基準，要求 WAIT/HOLD 說明具體重新評估條件，縮短重複敘述。
- 下單前獨立審查只帶實際提議交易的標的，保留那些標的的完整日線、持倉計畫及原風控。
- 每次主代理與支撐研究回覆即保存 `api_usage_requests.json`，包括快取、寫入快取、推理 token 和回覆 ID。中途解析失敗仍留下已完成請求用量；逾時或 API 失敗則標示用量不完整。
- 決策與支撐研究共用 `AGENT_MAX_INPUT_TOKENS`，預設 180,000：已記錄輸入達門檻後，不再發出下一次模型請求。單次請求仍可能使累計超過門檻，這不是絕對帳單上限；獨立下單前審查另計。預設最多 12 回合；既有環境變數仍可覆寫。
