## 如何節省用量

- 繼續預讀帳戶與交易歷史，避免模型先花一輪索取相同資料。
- 使用表格傳輸、日線摘要；完整資料仍可透過工具取得。
- 同一完整日線與成功觀察清單沿用快取，依價格／帳戶變化及既定時機重評。每小時仍取得行情並完成規則篩選；快取不是掃描失敗。
- 一批最多 40 檔供尋標比較、最多 6 檔加入查價，以及最多 3 個合格進場計畫進入主決策，仍屬候選批次設計，沒有改成全市場逐檔購買深度模型研究。
- 精簡重複敘述，但需要完整研究時可以延伸，不以文字長度拒收有效論證。

## 截斷恢復與完整用量

新增共用 `research_runtime.ResponseRecorder`，供尋標、主代理及其支撐研究、交易前審查使用。
正常請求不指定應用層固定輸出 token 上限。若供應商仍回傳 `incomplete / max_output_tokens`，
先保存該次實際回傳用量，再擴大同一步模型請求的輸出容量重試，沿用相同輸入及已完成的本機工具結果。
不重新執行本機研究工具、券商查詢或委託；託管搜尋可能再次執行，實際回傳的呼叫會納入記錄。

這是重試未完成的模型步驟，不是把半份 JSON 當成完整決策，也不是重做整輪掃描。
沒有固定的應用層重試次數額度。API 每次嘗試的輸入／輸出均加總；審查失敗時亦可從獨立用量檔核對。
未回傳用量的網路錯誤仍標示帳務不完整，不能報成零成本。供應商的模型容量或服務錯誤仍可能使請求失敗，沒有假設外部 API 永遠可用。

## 長時間研究與停止

主代理沒有預設總輪數或整輪時間額度。監督程式改為檢查同一程序的實際研究進度；
即使整輪超過十五分鐘，只要仍有新的請求／回覆進度，就不以總耗時重啟。
UI 心跳停止、真正長時間沒有進度、單次網路逾時，以及使用者停止要求仍保留處理。
未完成或無法驗證的決策不會取得下單權限。
