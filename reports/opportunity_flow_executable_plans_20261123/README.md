## 今日觀察

以下均以台灣時間及原正式帳本為準。今日共有 98 次研究 CLI 呼叫，researcher、challenger 各 49 次，資料庫全部記為 VALID；涵蓋 136 組配對研究。配對結果為 112 組 WATCH、23 組 REJECT、1 組 READY。這些是研究版本數，包含相同股票多次重審，不代表不同股票數。

唯一雙方通過的 3023 計畫於 13:14 完成，原定 279.5 元、4 股、失效價 270 元、目標 311 元。當時模型估算損失 48.196 元、費後利益 115.64 元，所需資金約 1120.118 元。最近有效對帳的新買可用額為 4080 元，因此這一筆的主要阻擋並非可用額不足。

研究端把行情正規化時丟掉日內高低價，選用了日內早已觸及的 270 元歷史支撐。原執行器之後依整個交易時段的低點檢查，回覆 `REVIEWED_PLAN_INVALIDATED_THIS_SESSION`。13:29 的最後執行報告仍為這個原因。初次執行亦遇過無法使用的行情；現有資料不足以把所有歷史 UNAVAILABLE 都歸因於本次找到的空回呼問題。

截至本報告匯出，今日正式執行資料庫中，`execution_attempts` 及 `execution_events` 的當日記錄均為 0，AI 帳本合計持股為 0。本次沒有製造實盤測試單。這些數字涵蓋本系統的正式帳本，不用來判斷使用者在其他介面送出的人工委託。

## 修正後流程

1. 初步候選先進券商取價佇列。正式帳戶模式必須取得有效零股行情及日內低點，才交由兩位研究代理敲定計畫。等待取價的候選在介面顯示「計畫行情核對中」。
2. 正規化行情保留開、高、低；選失效價時，排除已被當天低點碰到的歷史支撐，從原有結構支撐中選出有效位置，重新計算股數及費後條件。沒有有效支撐或經濟條件不合格時維持阻擋。
3. 研究就緒顯示與原執行器共用失效、目標及計畫限價規則，並依實際嚴格／建議模式對齊資料查核。計畫限價模式可依原價掛單；不會追高改價。政策變更則要求重新審查。
4. 新增 `E_INTRADAY`，把當前價格、日內範圍及前高／均線觸發狀態交給兩位代理。提示詞明確區分上一根完成日線與目前盤中價格；WATCH 要說明既有價位、時間尺度及失效條件，避免一律等待下一根日線。提示詞版本已更新以重審舊快取。
5. 複核後再次檢查凍結計畫。若市場新增低點跌破原失效價、目標已達、資金或資料不再合格，仍停止送單。拒絕明細保存複核理由、行情及原計畫價位，方便後續檢討。
6. 券商行情訂閱收到空快照時繼續等待有效回呼，不因已收到股票代碼就提早結束取價。
7. 版本驗收比較實際程式差異。僅新增報告、文件或 README 的提交不再造成版本不一致誤警；修改執行程式仍會被偵測。

## 驗證與實機狀態

新增 11 項測試涵蓋研究到複核及執行介面、重新選擇支撐及縮減股數、新低失效、沒有有效支撐、計畫限價、行情正規化、複核否決明細、缺低點先等待行情、空回呼後取得有效行情，以及程式版本判別。

正向整合驗證實際呼叫既有執行器，使用隔離帳本及模擬券商回覆確認部分成交 2 股，並驗證帳本回寫及重送防護。這是離線整合證據；沒有實盤成交證據。

`focused_regression.txt` 記錄 11 項全部通過，`full_regression.txt` 記錄 873 項全部通過，無失敗、錯誤或略過。離線執行器會封鎖外部網路及真實模型呼叫，使用暫存帳戶設定及帳本。

舊監護程序及交易子程序已正常關閉，確認 dashboard、broker-runtime、flow-supervisor 三個鎖全部釋放後，才由原入口啟動新版。新版程式心跳、版本核對、巡視迴圈及 Windows 啟動排程已觀測；券商同意書錯誤使新對帳及自動交易驗收尚未通過。日線資料已更新至 11 月 23 日。當前盤外不會進行盤中研究或送單。

`verification.json` 保存當日交易統計、凍結通過計畫、離線測試結果、脫敏實機檢查及目前阻擋。`review_prompt.json` 保存新版研究角色、規則及回覆結構。修正改善已通過計畫到執行端的條件一致性；明日盤中是否出現合格計畫、能否通過即時複核與券商確認，仍須實際行情驗證。
