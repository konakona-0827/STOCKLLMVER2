2026-11-12，分支 `codex/new-system-tw-opportunity-flow`。延續影子基線 `f02ea94`，整合本機最新 `codex/profit-exit-strategy` 的 `cdaa644`。遠端更新已 fetch；原正式程式的帳戶根目錄與費用設定維持不變。

操作流程與各項間隔另見 [完整流程圖與說明](../../docs/OPPORTUNITY_FLOW.md)。

## 結果與驗證界線

- 全套 **674 項測試通過**，72.118 秒；其中新增正式串接測試 37 項。原先影子核心的 34 項與最新退出分支測試均包含其中。
- 買進控制案例從凍結研究、研究員／反證員、下單前複核，走到原 `execute_advice_file`。模擬部分買進確認 2 股，正式格式的隔離帳本只增加 2 股；同一決策重跑不重送。
- 賣出控制案例在 BUY 可用額為零時走到同一原執行器。AI 10 股、人工 20 股，提出賣 5 股、模擬確認 2 股，AI 帳本成為 8 股；人工持股不納入賣出數量。
- 人工轉交以原持股配置的雙資料庫交易更新，寫入成本來源、轉交股數與「原買進計畫未知」旗標，不建立假的 BUY／成交紀錄。部分賣出後成本仍延續，另一次交接可按剩餘股數加權。
- Windows PowerShell 5.1 啟動器的 Check 與 Demo 均成功；Python 編譯檢查通過；Tk 成本欄位的測試不啟動券商。
- 本次驗證 **沒有登入實際券商，沒有送出實盤委託**。靜態 `ready=true` 表示依賴與原設定齊備，不代表券商連線、憑證、額度或實際成交已驗證。當日登入、零股市場行情與回報仍由開盤試運轉驗證。

完整回歸輸出在 [regression.txt](regression.txt)，機器可讀紀錄與來源雜湊在 [acceptance.json](acceptance.json)。舊 [1.0 報告](../opportunity_flow_20261112/README.md) 是當時的研究結果，不能當成 1.1 的成交證據。

## 接上的流程

`OpportunityFlow.cmd` 無參數啟動正式 Tk 介面；`RunOpportunityFlow.ps1 -Mode Live -Headless` 提供等同 CLI。`-ReadOnly` 可查詢但不送單、不撤單、不交接。原 `Demo / Cycle / Watch` 仍是影子入口。

新研究沿用免費完整日線與 Codex CLI；以真實帳戶可用額、現有持倉成本及風險重新計算股數。兩方須同意同一固定價量路徑，才能交給既有的獨立下單前複核。送出前再次更新帳戶、零股買賣價、持股及政策。原執行器保留資金、當日買入不可賣、人工股數、可賣量、未結單、成交確認與撤單確認控制。

持倉檢查獨立於新買進名單；同一執行 worker 序列處理，研究另在背景。執行器忙碌時，已完成研究會保留排隊。日線收集失敗或尚未完成時，用最後一份完整資料繼續檢查已持股，不用過期日線新開倉。冷啟動沒有完整快取時，須先完成資料建立；本機已備有 65 交易日完整快取。

各股管理沿用最新 `position_manager` 與 `profit_exit`，可 HOLD、SELL、預掛停利或撤掉本系統停利單。`RESEARCH_ADD` 只作研究請求，不能跳過兩方研究與數值風控直接加碼。原計畫未知時，模型按輸入成本、完成日線、實際觀測、當前買價與風險審查，不補造買進理由或買進日期。預掛是否可用仍服從原帳戶 `planned_limits_enabled`；目前為關閉。

## 失敗情況與對策

| 失敗或變化 | 對策與測試依據 |
|---|---|
| 模型 JSON 無效、逾時、額度／服務失敗 | 研究與服務錯誤明列、退避；個別持倉模型失敗不終止另一檔的新買進流程 |
| 研究完成時持倉 worker 忙碌 | 保留待執行研究；持倉排程不永久占住 BUY |
| 資金減少、持股變動、政策不同、計畫被改寫 | 下單前刷新並阻擋，原執行器另核對預期 AI 股數及固定股數／限價 |
| 試撮、過期報價、整股參考價 | 不作零股送單證據；模型完成後再刷新行情 |
| 上市／上櫃或未知市場混淆 | 依官方名錄分市場 5／6；逐市場隔離錯誤，未知不猜上市 |
| SELL 只有買一價／BUY 額度零 | 獨立檢查可賣量；不因缺賣一價或無買進預算停住退出 |
| 獲利退出複核後價格跌回虧損 | 阻擋舊獲利理由；原假設失效等風險退出仍可容許虧損 |
| 部分成交、只受理未成交、晚到回報 | 只計確認成交；沿用原未結單與對帳，不能重複賣出／撤單後立刻再賣 |
| 同決策重啟重跑、送出後回應中斷 | 新永久交接帳本加原 executor decision_id 雙層防重送；未知狀態不自動補送 |
| 交接股數過大、成本未知／NaN、待核對委託 | 原原子交易拒絕；無核實券商成本就要求明確輸入，不拿市價代替 |
| 日線下載失敗、程序中斷、讀寫同時發生 | 背景更新、重試退避、資料 SHA 檢查；OS 鎖保護整段讀寫，新格式殘留標記可在重啟後恢復 |
| 舊格式 `.collecting` 無法判別是否仍有收集程序 | 顯示 `LEGACY_MARKER_REQUIRES_REVIEW`，保持阻擋；不擅自刪除可能仍有效的舊鎖 |
| 月中關閉程式、跨月恢復時日曆少了一段 | 只有月結束後取得的月份日曆可永久重用；不把月中快取當成完整月份 |
| 停止發生於模型、COM 排隊或 session health 期間 | 停止訊號傳遞至原 executor，券商 SDK 送單前再檢查；已送出委託仍待券商確認 |
| 舊程式占用相同帳戶 | 原 OS account lease 阻擋第二個執行器，不強制關閉舊程式 |

上述新測試在 [test_flow_execution_bridge.py](../../tests/test_flow_execution_bridge.py)。最新分支的撤單與獲利退出測試在 `test_position_exit_cancel.py`、`test_profit_exit_integration.py`、`test_profit_exit_position_manager.py`；全部列在回歸輸出。

## 「找不到機會」的費用敏感度

本機正式設定沒有明確 `minimum_commission_twd`，因此原執行器沿用 `min_buy_fee_reserve_twd=20` 作保守最低佣金假設。這是設定假設，沒有核對券商實收費率。正式模式保留它；不把影子版每邊 NT$1 偷換進正式判斷。

以同一份 1,990 檔、65 個交易日日線，2026-11-12 08:30 截點、資金 NT$10,000、單檔 50%、風險 0.5%、淨收益 NT$50／2% 重算：

| 最低佣金假設（每邊） | 數值合格待研究 | 經濟條件未過 | 其他狀態 |
|---|---:|---:|---|
| NT$1 | 6 | 59 | 流動性未達 1,301、資料問題 177、無型態 447 |
| NT$20（目前正式假設） | 0 | 65 | 同上 |

這是收盤價數值情境，沒有即時券商行情、帳戶核對或模型批准；不是實際交易機會或績效。它指出費用假設與小額風險預算可能排除候選，不能一律歸因於 LLM 或執行器卡住。若之後取得券商真實費率，應明確更新正式佣金設定再重測；本次沒有更改風控以強迫成交。詳細分母在 [fee_sensitivity.json](fee_sensitivity.json)。
