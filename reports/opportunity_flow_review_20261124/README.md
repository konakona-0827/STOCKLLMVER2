## 本次修正

1. Windows 原子寫入使用各次獨立暫存檔；替換遇 WinError 5／32／33 時最多四次嘗試，總等待 85ms。持續錯誤仍失敗，最後完整檔案不被截斷。心跳記錄累計失敗及恢復時間，寫入診斷失敗不打斷 GUI／巡視。Windows 分享模式對重新命名的影響依 [Microsoft CreateFile 文件](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea)，錯誤碼依 [官方定義](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-)；這不能識別歷史上實際持鎖的外部程式。
2. 心跳單次讀取失敗保留上次同 PID／run_id 的資料及原時間，不再把運行中程序誤當「從未產生啟動心跳」。持續過期仍觸發原正常恢復，不強殺金融 owner。
3. 每分鐘重複啟動不再覆寫主守護的報告。保留遠端已新增的報告提交相容判斷，另加入啟動時的內容指紋，核對實際程式、策略、提示詞與設定；相同 SHA 但內容不同也不能認定相同版本。
4. 整合原正式啟動入口的版本交接：僅對已辨識的當前程序請求正常退出，等待守護、介面、券商三鎖釋放，再由新守護重新對帳並進入原自動流程；人工停止取消恢復。既有金融動作未完成時繼續等待，不移除帳本鎖、不刪防重送紀錄。
5. 下單前複核另存脫敏理由與驗證結果，區分模型呼叫成功和真正批准。額外診斷不重問模型、不重送委託。研究、複核、送單及持股退出仍由原正式路徑執行；保留最新行情完整性與輪替修正。
