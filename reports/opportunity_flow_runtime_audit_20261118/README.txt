2026-11-18 正式入口實機檢查與自動匯出整合

基線：a906407a9e73a9f5785a6f5126032e581720a8e8
分支：codex/new-system-tw-opportunity-flow

需求
前次已有 Windows 重開機恢復程式，但交易電腦若沒有匯出新收據與執行證據，
Git 遠端就只能看到修復前停止的狀態。這次把實際設定讀回、運行驗收及可供
Git 保存的日誌匯出接入同一 OpportunityFlow.cmd 正式入口。

更新後的使用方式
交易電腦拉取更新後照常啟動一次 OpportunityFlow.cmd。原流程自動安裝／
修復恢復設定，再啟動守護程序與原正式 Live 流程。啟動視窗等候本次程序、
新券商對帳與研究監看，最多 180 秒；背景流程持續運作。Headless 亦先查
初次帳務再等日線更新，保留 Ctrl+C 手動暫停。

實機設定讀回
安裝器新增僅供內部使用的 InspectOnly 分支，從 Windows Task Scheduler
及本人 Startup 捷徑讀取目前實際設定，不把舊 task-registration.json 當成
安裝成功的證據。核對目前程式、帳戶、資料／狀態路徑、執行參數、本人互動
工作階段、觸發、停用狀態及與舊排程的衝突。檢查不註冊或變更 OS 設定。
守護程序每 60 秒在獨立背景工作讀回，最多等待 25 秒，不占券商 owner。

執行證據
RecoveryProbe 保存目前 PID、run_id、程式版本、GUI／watch 心跳、新對帳
時間及階段。驗收要求本次啟動後的新對帳及相同版本；舊程序的心跳、舊帳務
或舊研究事件不能變成這次的成功。程序存在本身不算研究／送單已完成。

原流程記錄：重新對帳、開始 watch、等日線、盤外等候、數值掃描、兩方研究、
下單前複核、原執行器派發與回覆、實際送單、確認成交、持股管理、執行阻擋。
券商回覆不明另列 DISPATCH_UNKNOWN／unknown_events；不把未確認當成未送單，
也不改變原帳本的待對帳或禁止重送規則。此計數保存本次曾發生的不明事件。

自動匯出
reports/opportunity_flow_runtime/latest.txt：中文檢查結果。
reports/opportunity_flow_runtime/latest.json：機器可讀的實機報告。
reports/opportunity_flow_runtime/runs/*.json：各次程序的最後報告。
原帳戶 data/health/flow_recovery/runtime-audit.json：帳戶副本。
報告每 30 秒或狀態改變時保存，包含階段彙總及最近 100 個白名單事件。
Git 目錄不能寫時，帳戶副本明列匯出錯誤；觀測寫檔失敗不能改變送單結果。
匯出檔可隨原本 Git 提交一併推送；啟動器不自動 commit 或 push。

狀態不混用
AUTOMATION_ACTIVE 要求實際啟動設定、目前程序／版本、新對帳、自動控制器
及研究掃描。盤外為 WAITING_RESEARCH_WINDOW；等日線、研究錯誤、舊 owner、
版本不同、手動暫停、安裝或啟動失敗各自列示。較新的日線等待／研究錯誤
不會被較早的成功掃描遮蔽。送單與成交另按原執行器回報記數，不預填成功。

風控及隱私
不改策略政策、交易帳戶設定、原自動委託執行器、資金核對或 pretrade_policy。
ExecutionBridge 只增加旁路觀測；原研究、複核、行情、費後、風險、時段、
人工持股、圈存、日額及防重送仍執行。保留額與 AI 上限保持獨立。驗收沒有
額外買賣腳本，不為取得成交紀錄改條件或派測試單。
匯出只允許固定欄位，排除帳號、憑證、私人路徑、模型原文及原始 SDK 回覆。

測試（精確總數與輸出見 verification.json／regression.txt）
- 實際 Windows 暫存帳戶註冊／讀回／清理；依本機權限驗證完整排程或登入
  捷徑，清理後保留舊收據仍不能再聲稱自動啟動有效。不改正式排程。
- Windows 缺少實際物件時檢查必須失敗，不得只讀安裝計畫就通過。
- 真實隔離子程序送出當次心跳，由真正守護程序收集並自動匯出 ACTIVE；
  子程序保存手動暫停後匯出 MANUALLY_PAUSED。無真實券商或模型。
- 相同 PID／不同 run、不同版本、舊快照、過期心跳、只讀、停用、不明回覆、
  盤外、資料等待、研究錯誤、敏感欄位過濾及匯出磁碟失敗。
- 原 watch + LiveCoordinator + ExecutionBridge + 原 execute_advice_file 的
  隔離完整流程：新對帳、兩方研究、BUY 複核、原送單類別模擬成交、AI 帳本、
  自動管理、SELL 複核與模擬成交。觀測送單／成交均 2 個，無手動派發，AI
  股數歸零，保留另外 3 股人工股數。
- 純背景啟動必須先對帳，日線下載工作才能開始；不因下載延誤初次帳務查核。
- 實際 OpportunityFlow.cmd -Mode Check 通過，退出碼 0，不登入券商或送單。
- 全套離線回歸封鎖外部 Python 網路與真實 Codex 呼叫，包含原所有風控測試。
  既有 Tk UI 拆卸的 ThemeChanged 訊息不屬 unittest 失敗。

中途一輪回歸發現既有策略版本測試偶發失敗：兩筆匯入時間可能同一個時鐘
tick，清單以時間及隨機 ID 排序，測試用第二列誤認第二個帳戶。已只修測試，
改以建立時取得的帳戶 ID 核對，並固定同一時間重現此情境；原策略儲存及
交易程式保持不變。之後重新執行全套驗證，未跳過該測試。

部署邊界
本次提交的是自動檢查與匯出功能，未在交易電腦實際登入或重開機，也沒有
實盤測試單。交易電腦拉取更新並啟動一次後，報告才會反映該電腦的事實；
不預造驗收成功。Windows 帳戶仍須登入且原券商／Codex 憑證有效。權限不足
時登入啟動只列 OWNER_LOGON，完整開機及每分鐘排程需要註冊權限。若同帳戶
舊程序仍存活，保留原 owner，明列衝突並等待正常退出，不強殺或開第二個。
